# Sprint 4 — AI Inbetweening 0.5.0

**Une animation produite par un réseau neuronal entraîné a été importée, retargetée et validée dans Blender.** Cette preuve porte sur une chaîne FK planaire à trois os, **pas sur un personnage Rigify**. Les clips humanoïdes de garde, attaque, esquive et récupération, ainsi que la correction de prise d’arme et des contacts IK après inférence, ne sont pas livrés. Le parcours CPU de production reste inchangé.

## Utiliser le modèle

1. Installer le [ZIP 0.5.0](../dist/souls_animation_studio-0.5.0.zip) depuis le disque. Pour Linear/Smooth et Rigify, aucun autre fichier ni dépendance IA n’est nécessaire.
2. Préparer un Python externe avec NumPy. Sur la machine de recette, NumPy était déjà présent : `python3 -m venv --without-pip --system-site-packages /chemin/absolu/sas-mlp`. Sinon, créer un venv standard et y installer NumPy, par exemple `…/sas-mlp/bin/python -m pip install numpy`, ou installer depuis un répertoire de wheels compatible (`--no-index --find-links`). Ne pas installer dans Python Blender. Vérifier `…/sas-mlp/bin/python -c 'import numpy; print(numpy.__version__)'`.
3. Ouvrir le [banc Blender](../demo/sprint4-planar.blend) sans auto-exécution. Pour refaire une génération, rendre visible et sélectionner le rig CTRL du panneau MLP, puis lui assigner **`MLP | SOURCE - 4 ancres`** (garder l’Action de comparaison séparée). Dans **N → Souls Animation Studio → AI Inbetweening — Experimental**, ouvrir le dialogue. Fournir les chemins absolus vers le Python externe, le [worker](../backends/inbetweening/sprint4_worker.py) et les [poids originaux](../demo/sprint4-planar.f32) ; ne confirmer la confiance que pour des fichiers vérifiés. Le worker, les poids et NumPy sont hors ZIP. Il n’y a aucun téléchargement automatique.
4. Indiquer `Base CTRL`, `Pivot CTRL`, `Bout CTRL` dans l’ordre et choisir les bornes **1–25** à **24 i/s**, sans remappage. Le profil exige 2 à 6 poses complètes, des canaux et un repos compatibles, sans NLA, contraintes de contrôle ni contacts. Pour la démo, les ancres sont `[1, 7.5, 16, 25]`. Pas de prompt, pose partielle ni seed d’inférence : le worker est déterministe.
5. Lancer le job ; suivre les étapes ou annuler par **Échap** / **Annuler**. Une erreur ou une annulation ne laisse pas d’Action et ne déclenche pas Linear/Smooth. En cas de succès, sélectionner la nouvelle Action dans l’Action Editor : elle est conservée mais non assignée automatiquement. Cette procédure en fenêtre reste à recetter ; l’automatisation couvre le worker, l’écriture d’Action et le cycle modal avec événements injectés.

CondMDI et son dérivé MoLab n’ont pas été qualifiés pour cette livraison ; les poids UniMate examinés sont non commerciaux. Les sources, poids et démonstrations correspondants sont sous GPL-3.0-or-later ; conserver la notice, la licence et les sources associées en cas de redistribution séparée. NumPy est externe.

Hôte : Ryzen 5 3600 (6 cœurs / 12 threads), 23,35 Gio RAM visibles, Radeon RX 6600 Navi 23 `gfx1032` (7,98 Gio VRAM), `amdgpu`, Linux CachyOS ; Python externe 3.14.10 / NumPy 2.5.5, Blender 5.2.1 LTS / Python 3.13.13, Godot 4.7.2. Aucun CUDA. Une sonde HIP indépendante a vérifié un calcul élémentaire sur le GPU ; **ni PyTorch ROCm ni un modèle GPU n’ont été validés**. L’inférence livrée n’utilise que le CPU.

## Résultats et limites

- **Vraie génération.** Les deux couches cachées prédisent directement les six canaux, sans complément interpolé. Sur la preuve à quatre ancres, 22 poses finies, quaternions unitaires ; variation mesurable en changeant une ancre intérieure. La seed d’entraînement est `4072026`. Sur 40 jobs, **97,1 ms** médians de bout en bout, **43 284 Kio** de RSS maximale enfant ; entraînement environ **44 s**. La répétabilité à l’octet a été vérifiée sur la même pile.
- **Retarget.** Le contrat v1 porte les poses locales absolues avec hiérarchie, WXYZ et unités métriques. Le mapping explicite convertit les axes locaux du rig planaire. La copie vérifie les clés, y compris fractionnaires ; la démo vérifie aussi l’égalité des matrices aux ancres, la FK et les sommets d’un skin DEF distinct. Aucun contrôleur Rigify exporté comme joint anatomique. Les ancres sont conservées au bake, pas garanties par les prédictions brutes du réseau.
- **Comparatif contrôlé.** [Planche et `.blend`](../demo/sprint4-planar-README.md) : sur les mêmes quatre ancres et la même référence inédite, erreur RMS au dernier joint **4,70 cm en Linear, 5,45 cm en Smooth et 10,40 cm pour le MLP**. Sur 40 clips de la famille synthétique, RMS de racine **0,189 m contre 0,211 m** (Linear puis MLP). La [sonde de continuité](sprint-4-continuite.md) mesure des différences finies sur les poses canoniques ; elle met en évidence des pics de vitesse et d’accélération près d’ancres MLP. Ce modèle expérimental ne justifie pas de remplacer Linear/Smooth. Pas de mesure de pied-sol, d’accélérations sur un humanoïde, ni de banc des cinq clips de combat demandés. Une sonde négative sur cible mobile a mesuré puis rejeté les résidus hors tolérance ; le pipeline livré refuse les contacts au lieu de prétendre les résoudre.
- **Export neuronal.** [GLB original](../demo/sprint4-planar.glb) : clip d’une seconde, root motion, trois os DEF et une peau. Contrôle de 49 demi-images avec cuisson 48 Hz pour conserver l’ancre fractionnaire : 0,80 µm d’écart maximal de sommets au réimport Blender et 0,63 µm pour les têtes d’os dans Godot temporaire, avec l’optimiseur désactivé. Aucun accessoire dans le GLB neuronal ; le GLB accessoire Sprint 3 reste couvert par sa sonde historique, sans nouvelle qualification sur un clip IA.

## Tests et suite

La suite standard teste le ZIP installé hors ligne, les 57 cas historiques, les fixtures de processus (absence, délai, annulation et erreurs) et le retarget planaire. Le chemin explicite `SAS_MOTION_TEST_PYTHON=/chemin/absolu/venv/bin/python SOULS_TEST_GODOT=1 bash scripts/test_headless.sh` ajoute le checkpoint entraîné, le bake réel, le GLB et l’import Godot. Voir [la recette des tests](../tests/README.md).

Recette indépendante : **76 tests réussis**, 0 échec et 7 skips de répartition CPython/Blender (les cas passent dans l’autre environnement), avec et sans l’option checkpoint. Hors décompte : retarget planaire, bake réel dans la suite optionnelle, trois sondes Godot et deux contrôles de remontée d’erreur. L’avertissement `blender_org` absent au retrait n’a pas empêché la désinstallation vérifiée. Ni la recette interactive ni Windows n’ont été validés.

Priorité suivante : qualifier un modèle humanoïde et ses droits, réaliser un retarget rig-to-rig préservant les proportions, puis brancher le solveur de contacts après bake. Avant une activation générale, vérifier aux mêmes ancres les discontinuités adjacentes, la trajectoire, le glissement, l’arme et la fidélité d’export sur les clips de combat demandés.
